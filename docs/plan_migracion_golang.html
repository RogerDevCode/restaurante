💡 Decisión de UI: HTMX + Templ (no SPA)

El proyecto actual usa Swing (desktop). La migración a Go convierte la app en web, accesible desde cualquier navegador — tablets incluidas. La combinación HTMX + Templ + Tailwind es ideal porque:

  • Sin framework JavaScript pesado (React, Vue) — menos complejidad, menos dependencias
  • Templates compilados en Go (Templ) — type-safe, rendimiento nativo
  • HTMX da interactividad SPA-like con atributos HTML — el servidor controla todo
  • WebSocket nativo para actualizaciones en tiempo real (mesas, comandas)
  • PWA para que tablets funcionen como app nativa (offline-first con service worker)
  • Un solo binario Go contiene todo: backend + frontend + assets (go:embed)

Manejo de Dinero — Tipo Money

⚠️ Regla fiscal inquebrantable

2 decimales de punta a punta. Aritmética intermedia con 8 decimales. Redondeo único HALF_UP al límite de línea/pedido. Σ desglose == cabecera.

// internal/domain/money.go
package domain

import "github.com/shopspring/decimal"

// Money representa un monto monetario con 2 decimales exactos.
// Aritmética intermedia usa 8 decimales; redondeo HALF_UP solo al materializar.
type Money struct {
    amount decimal.Decimal
}

const (
    ScaleFinal       = 2
    ScalaIntermedia   = 8
)

func NewMoney(v decimal.Decimal) Money {
    return Money{amount: v.Round(ScaleFinal)}
}

func (m Money) Mul(rate decimal.Decimal) Money {
    // Intermedio a 8 decimales, redondeo final a 2
    return Money{amount: m.amount.Mul(rate).Round(ScaleFinal)}
}

func (m Money) Add(other Money) Money {
    return Money{amount: m.amount.Add(other.amount)}
}

func (m Money) Decimal() decimal.Decimal { return m.amount }
func (m Money) String() string           { return m.amount.StringFixed(ScaleFinal) }

    db := mysql.NewPool(cfg.DatabaseURL)
    defer db.Close()

    pedidoRepo   := mysql.NewPedidoRepo(db)
    platoRepo    := mysql.NewPlatoRepo(db)
    salaRepo     := mysql.NewSalaRepo(db)
    configRepo   := mysql.NewConfigRepo(db)
    cierreRepo   := mysql.NewCierreRepo(db)
    // ...más repos...

    printer      := printer.NewEscPos(cfg.PrinterAddr)
    pdfGen       := pdf.NewFacturaGenerator()
    licValidator := security.NewLicenseValidator(cfg.LicensePath)

    // Servicios de dominio
    calcMon    := service.NewCalculoMonetario()
    pedidoSvc  := service.NewPedidoService(pedidoRepo, calcMon)
    cobroSvc   := service.NewCobroService(pedidoRepo, configRepo, printer, pdfGen)
    cierreSvc  := service.NewCierreService(cierreRepo, pedidoRepo, configRepo)
    comandaSvc := service.NewComandaService(pedidoRepo, printer)
    authSvc    := service.NewAutenticacionService(usuarioRepo, licValidator)
    // ...más servicios...

    // Adaptadores primarios (HTTP handlers)
    r := chi.NewRouter()
    r.Use(middleware.Logger, middleware.Recoverer)
    handler.RegisterRoutes(r, pedidoSvc, cobroSvc, cierreSvc, comandaSvc, authSvc)

    // Servidor
    srv := &http.Server{Addr: cfg.ListenAddr, Handler: r}
    go gracefulShutdown(srv, db)
    srv.ListenAndServe()

Patrón de transacciones en Go

// internal/adapter/mysql/tx.go
type TxFunc func(ctx context.Context, tx *sqlx.Tx) error

func (db *DB) WithTx(ctx context.Context, fn TxFunc) error {
    tx, err := db.BeginTxx(ctx, nil)
    if err != nil {
        return fmt.Errorf("begin tx: %w", err)
    }
    defer func() {
        if p := recover(); p != nil {
            _ = tx.Rollback()
            panic(p) // re-throw después de rollback
        }
    }()
    if err := fn(ctx, tx); err != nil {
        _ = tx.Rollback()
        return err
    }
    return tx.Commit()
}

8.3 — Errores comunes a evitar

🚫 Anti-patrones
  • No crear un ORM — usar sqlx con queries explícitas, como el Java actual
  • No usar gorilla/mux — está archivado, usar chi
  • No poner lógica de negocio en handlers — handlers solo: parsear request → llamar servicio → formatear response
  • No usar panic para control de flujo — siempre return err
  • No usar init() — DI explícita en main.go
  • No usar float64 para dinero — solo shopspring/decimal
  • No migrar SwingWorkers — HTMX maneja asincronía nativamente
  • No crear getters/setters — campos exportados directamente
  • No usar herencia — composición con embedding
  • No ignorar context.Context — propagar siempre
